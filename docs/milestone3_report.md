# Milestone 3 — Statistical Screener Engine

*15 November 2026. Source of truth: Statistical Screener Specification v1.2.*

## 1. How to run it

```bash
uv run diski9 init-db                        # applies migration 0002
uv run diski9 ingest-fixtures                # loads venue overrides + approved home grounds, updates fixtures
uv run diski9 screener-refresh --days 14     # compute + cache results (venue and overall basis)
uv run diski9 screener-show --direction home_stronger   # | away_stronger | evenly_matched
uv run diski9 screener-show --direction btts_yes        # | btts_no | over | under
uv run python scripts/validate_benchmark_threshold.py   # benchmark threshold validation
uv run diski9 analyse-odds-trial --out docs/odds_trial_interim.json
```

## 2. Calculations implemented (`src/diski9/screener/`)

All arithmetic uses exact fractions. Display values are rounded half-up.

| Spec | Implementation |
|---|---|
| 4.2 Form Score | `PPG + 0.5 × clip(GD/G, −2, +2)`, bounded [−1, 4]. The breakdown shows W/D/L, points, GF, GA, GD, PPG, GD/G, capped GD/G, the weighted contribution and the score |
| 4.4 Windows | Default: home team's last 5 **home** matches vs away team's last 5 **away** matches, chosen from full history (not filtered from the last 5 overall). An overall basis is also available |
| 4.5 / 4.6 | Raw difference and venue-adjusted difference. On the overall basis only the raw difference applies, because the league benchmark would be identical for both teams |
| 4.7 Benchmarks | The Form Score formula applied to **pooled** eligible league results: home wins, draws and home goal difference, and the mirror for away. It is not an average of team scores. The current season is used once it has at least 120 eligible matches; otherwise the previous completed season; otherwise a flagged partial current season. Output includes the season, source, sample size and draw rate |
| 4.8 Ranking | Home stronger, away stronger, evenly matched (closest to 0), with an optional threshold. A near-zero difference is explicitly *not* read as a likely draw |
| 5 BTTS | Last 10 venue-specific matches per team, team rates as k/n (%), combined simple average, No = 100% − Yes |
| 6 Over/Under 2.5 | Same structure; Over means ≥ 3 goals in the 90-minute score |
| 9 Details | Underlying matches (date, opponent, competition, H/A, score, W/D/L, BTTS, O2.5, provenance, unverified-venue flag). Also: averages, clean sheets, failed-to-score, a computed league position, and up to 5 head-to-head meetings (flagged "older" if more than one season back) that do not affect any indicator |
| 10.2 / 10.3 | Windows extend into earlier seasons and lower divisions. Each match is labelled `current_season_same_division`, `previous_season_same_division` or `other_division`, with the note "Includes N previous-division/other-competition matches" |
| 10.4 Limited data | Independent flags: fewer than 3 Form matches, fewer than 6 goals-market matches, fewer than 3 current-division matches. The indicator is still shown when n ≥ 1 |
| 10.5 | The real sample size is always shown. No indicator is produced when the denominator is 0 |
| 10.6 Point-in-time | `cutoff = min(as_of, kickoff)`. Only matches that kicked off before the cutoff are used, for windows, benchmarks, head-to-head and the table |

**Relevant matches:**
* Included: domestic-league matches eligible for statistics, which are
  completed regular-season matches.
* Excluded: awarded, walkover, cancelled, abandoned and postponed matches, and
  play-off, relegation and promotion rounds.
* Confirmed `neutral` venues are excluded from venue windows and benchmarks.
* `unverified_venue` matches are kept (using the provider's home/away
  designation) and flagged in the output.
* Siwelele is a new team id with no inherited history.

**No probabilities, expected values or edges are computed.** Every output
carries the note "Historical indicators, not predicted probabilities."

## 3. Venue decisions applied

* **Dated approved-home-grounds list** in `config/approved_home_grounds.csv`:
  24 entries with evidence. An entry qualifies with at least 3 regular-season
  home league matches at the venue in a season, generated by
  `scripts/home_ground_evidence.py`. Examples: SuperSport United at Lucas
  Moripe and Peter Mokaba/Global Stadium; Sundowns at Lucas Moripe; AmaZulu at
  King Goodwill Zwelithini; Kaizer Chiefs at Moses Mabhida (2024/25).
* The classification `potential_neutral` was renamed **`unverified_venue`**
  (migration 0002), so a different stadium is never presented as neutral.
* Explicit **neutral** fixture overrides cover the 4 Championship play-off
  final rows at Wembley. One of them is a cancelled placeholder final the
  provider still lists.
* Result across all four competitions and seasons: PSL unverified venues fell
  from 89 (completed seasons alone) to 24 across all seasons; PSL 1st Division
  to 17. These remain flagged.

### Threshold validation

`docs/benchmark_threshold_validation.json` covers 8 completed seasons that
each have a stored previous season. The VAD depends on benchmarks only
through the gap (home − away), so the test measured how far that gap is from
its full-season value:

* Using the previous season's gap gives a mean error of **0.322**.
* A partial current season gives a mean error of 0.76 after 10 matches,
  0.31 after 60 (noisy: 0.35 to 0.40 between 70 and 100), and 0.27 or less
  from 120 onwards.
* The default is therefore **120** matches, the point after which the
  partial season is consistently no worse. It can be configured per league.
  For the PSL the previous season was a much better predictor (errors
  0.10 to 0.15) than for the EPL.

## 6. BTTS and Over/Under 2.5 (examples)

  Over 2.5 20% (Under 80%).
* **Liverpool v Man Utd:** BTTS 50%. Over 2.5 35% (Under 65%).

These are averages of two separate historical rates, **not** probabilities.

## 8. Odds monitoring trial (in progress)

* **Mechanism:** each run saves the raw odds pages (3 markets only, about
  13 KB gzipped) to `monitoring/odds_trial/`, committed to the branch, so the
  trial survives container restarts. `analyse-odds-trial` replays every run
  through the production reconciliation code.
* **Schedule:** a scheduled task fires into this session every 3 hours at
  :14 past, until **21 Nov 15:00 UTC**. That covers the run-up to the
  Saturday EPL kickoffs. Each run uses about 4 requests. The capture command
  refuses to run after the end time, and the task disables itself then. Two
  extra one-off PSL checks are scheduled for **25 Nov 12:07 UTC** and
  **27 Nov 11:07 UTC** (match day). No indefinite schedule exists.
* **Limitation:** the cloud container is ephemeral and no process runs between
  firings. If a firing is missed or delayed, that interval is missing from the
  data. Gaps are visible in `runs.jsonl`.

Interim findings (2 captures today, plus the Milestone 2 collections):
* The provider `update` value was still `03:24:17/18Z` at 11:21, about
  **7.9 h old**. It was identical across all 20 upcoming EPL fixtures and all
  bookmakers.
* No price changed between captures 8 minutes apart.
* Bookmakers listed per fixture: 10 at 3–7 days out, a median of 6 at 7–14
  days.
* PSL: no odds in any capture.

The full analysis, covering update frequency, price changes with and without
a provider-timestamp change, and coverage by lead time, follows when the trial
ends.
